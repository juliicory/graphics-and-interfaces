# Week Selector Burger Menu — Spec

## Goal
Add a burger-menu dropdown in the top-left corner of `index.html` that
lists each week's JS file as a labeled option. Selecting an option
switches which week's script drives the canvas on the page.

## Files changed / added
- `index.html` — replaced the hardcoded `<script src="week-2.js">` with
  the menu markup and a single `<script src="menu.js">`.
- `index.css` — added styles for `.week-menu`, `.menu-toggle` (burger
  icon), and `.week-list` (dropdown + options).
- `menu.js` — new file, owns all menu behavior and script loading.

`week-1.js` and `week-2.js` are untouched.

## Markup (`index.html`)
```html
<div class="week-menu">
    <button id="menu-toggle" class="menu-toggle" aria-label="Toggle week menu" aria-expanded="false">
        <span></span><span></span><span></span>
    </button>
    <ul id="week-list" class="week-list" hidden></ul>
</div>
<script src="menu.js"></script>
```
The `<li>` options inside `#week-list` are generated by `menu.js`, not
hardcoded, so adding a new week only means adding one entry to the
`WEEKS` array in `menu.js`.

## Behavior (`menu.js`)
- `WEEKS` is an ordered array of `{ label, file }` pairs (currently
  Week 1 → `week-1.js`, Week 2 → `week-2.js`).
- The active week is persisted in `localStorage` under `selectedWeek`.
  If nothing is stored yet, it defaults to the last entry in `WEEKS`
  (the most recent week).
- On load, `menu.js` renders one button per week inside `#week-list`,
  marking the current selection with an `active` class, then
  dynamically creates and appends the `<script src="<selected file>">`
  tag that actually runs that week's sketch.
- Clicking the burger toggles `#week-list`'s `hidden` attribute
  (`aria-expanded` is kept in sync for accessibility).
- Clicking outside the open menu closes it.
- Clicking a non-active week option stores the choice in `localStorage`
  and calls `location.reload()`.
- Clicking the already-active option just closes the menu (no reload).

### Why reload instead of hot-swapping the script tag
Both week scripts declare top-level `const`/`let` bindings (`canvas`,
`gl`, `mouse`, …) in the global scope. Classic `<script>` top-level
lexical declarations persist for the lifetime of the page, so loading
a second week script into the same page without reloading would throw
a "has already been declared" `SyntaxError` the moment a second script
redeclares the same names. Reloading the page guarantees a clean global
scope for whichever script is selected.

## Styling (`index.css`)
- `.week-menu` is `position: fixed; top/left: 16px` with a high
  `z-index` so it stays above the full-bleed canvas.
- `.menu-toggle` is a 40×40 dark rounded button with three white bars
  (pure CSS burger icon, no image assets).
- `.week-list` is a small dark dropdown panel below the button;
  `.week-option` buttons highlight on hover and get a stronger
  highlight + bold text when `.active`.

## Verification
Manually smoke-tested with a headless Playwright script against a
local static server (`python -m http.server`):
- Menu starts closed; opening it lists "Week 1" and "Week 2", with
  "Week 2" marked active by default.
- Clicking outside the open menu closes it.
- Selecting "Week 1" stores `selectedWeek = week-1.js`, reloads the
  page, and the menu reopens with "Week 1" now marked active.

Note: `week-1.js`'s own shader has a pre-existing GLSL error
(`'pct' : undeclared identifier`) unrelated to this change — it was
already present in that file before the menu was added.
